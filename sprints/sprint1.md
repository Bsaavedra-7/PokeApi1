## Retrospectiva

### Resultado de las mejoras del sprint anterior

- El equipo logró organizarse usando GitHub Projects de manera constante, evitando topes de trabajo.
- Se implementaron las reuniones cada vez que fue necesario, mejorando la comunicación general.

### Qué funcionó

- Las revisiones de Pull Request fueron rápidas y el equipo de desarrollo mostró buena velocidad de adaptación a los cambios.
- Cada integrante cumplió su rol y comunicó los problemas o dudas a tiempo para que todo el equipo buscara una solución al ser necesario.
- El trabajo fue bastante constante y muy ordenado, lo que permitió a todo el equipo entender bien que se estaba haciendo a cada momento.
- Las estimaciones fueron acorde a lo que creemos que le correspondía a cada User Story.

### Qué no funcionó

- Al inicio hubo problemas relacionados a las historias de usuario, que encasillaban la implementación técnica (ej. obligaban a usar un "botón") y no permitían que el equipo tuviera libertad creativa para trabajar.
- Tuvimos ciertos problemas de horario para definir cuando se harían ciertas reuniones, porque no todos los integrantes tenían la misma disponibilidad, pero siempre se solucionó muy rápidamente, cambiando o el día o la modalidad de la reunión.

### Qué podemos mejorar

- Lo que podríamos mejorar sería definir un mismo horario, en el que sepamos que todos los integrantes del equipo tienen disponibilidad, para hacer las reuniones en ese horario 
- Intentar dejar todo listo para el sprint review varios días antes.

### Plan de acción

- [ ] El Product Owner redactará las historias enfocadas en "qué necesita el usuario" y dejará el "cómo" libre para el equipo técnico.
- [ ] Realizar pruebas de usabilidad y contraste de colores en cada componente visual antes de pasarlo a la columna "Review".
- [ ] Se definirá un horario en el que sepamos que todos los integrantes del equipo tienen disponibilidad, para hacer las reuniones en ese horario.
- [ ] Intentar dejar todo listo para el sprint review varios días antes, por si se quiere implementar algo nuevo uno de los últimos días.
